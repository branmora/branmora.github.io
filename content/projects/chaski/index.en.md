chaski is a lightweight convention for solo developers and small teams who build with coding agents. A person and an orchestrator agent write one short spec per epic, and the person approves the set. From there the work runs on GitHub's own features: sub-issues carry the breakdown, blocking edges the order, and open or closed issues the state, so there is no second tracker.

Separate roles build and check the work. An implementer writes the code against checks written before it started, a reviewer who never sees the implementer's reasoning gives the verdict, and a change merges only when its tests pass.

The chaskis were the relay runners of the Inca road network, who carried messages across the Andes to Cusco, my hometown. The roles here pass the work along the same way.
